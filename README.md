# Meeting Room API

API для бронирования переговорных комнат. Разработано на Laravel 13 с использованием Docker, Redis, Sanctum и Swagger.

## 🛠️ Функционал проекта

### 1. Аутентификация и авторизация
- Регистрация новых пользователей с ролью `user`
- Вход по email и паролю, выдача Bearer токена (Laravel Sanctum)
- Выход — удаление текущего токена
- Защита маршрутов через middleware `auth:sanctum`
- Разграничение ролей: `admin` и `user`

### 2. Управление переговорными комнатами (CRUD)
- **Просмотр списка** всех активных комнат с пагинацией (доступно всем авторизованным)
- **Просмотр одной комнаты** по ID
- **Создание комнаты** — только для администратора
- **Обновление комнаты** — только для администратора
- **Удаление комнаты** — только для администратора
- Автоматическое кэширование списка комнат (Redis, 1 час)
- Инвалидация кэша при создании/обновлении/удалении комнаты

### 3. Поиск свободных комнат
- Проверка доступности комнат на конкретную дату и время
- Учёт уже существующих броней (исключая отменённые)
- Кэширование результатов (5 минут)
- Возврат списка комнат, свободных для бронирования

### 4. Бронирование переговорных
- **Создание брони** авторизованным пользователем
- Проверка пересечений по времени с другими бронями
- Блокировка строки комнаты через `lockForUpdate()` (защита от гонок)
- Автоматическое проставление `user_id` от авторизованного пользователя
- Статусы брони: `pending` (новая), `cancelled` (отменена), `confirmed` (подтверждена)

### 5. Отмена и удаление броней
- **Отмена брони** (статус → `cancelled`)
- **Удаление брони** (полное удаление из БД)
- Политики доступа:
  - Владелец брони может отменить/удалить свою бронь
  - Администратор может отменить/удалить любую бронь
- Проверка статуса перед отменой (нельзя отменить уже отменённую)

### 6. Просмотр броней
- **GET `/api/bookings`** — список всех броней (только для администратора) с фильтром `active`
- **GET `/api/user/bookings`** — список броней текущего пользователя
- **GET `/api/bookings/{id}`** — просмотр конкретной брони (владелец или админ)

### 7. Асинхронные уведомления (очереди + Redis)
- **SendBookingConfirmation** — отправляется при создании брони (через событие `BookingCreated`)
- **SendBookingReminder** — отложенная отправка напоминания за 15 минут до начала брони
- Все задачи уходят в Redis-очередь, не блокируют ответ API

### 8. События и слушатели
- **BookingCreated** — событие, диспатчится после создания брони
- **SendBookingConfirmationNotification** — асинхронный слушатель (реализация уведомления)
- Логика уведомлений отделена от основной логики бронирования

### 9. Кэширование
- **Список комнат** — 1 час (тег `rooms`)
- **Список свободных комнат** — 5 минут (тег `rooms.available`)
- Инвалидация при любом изменении данных через `Cache::flush()`

### 10. Политики доступа
- **RoomPolicy**: создание, обновление, удаление комнат — только `admin`
- **BookingPolicy**:
  - `viewAny` — только `admin`
  - `view` / `cancel` / `delete` — владелец брони или `admin`
- Автоматическая проверка через `$this->authorize()` в контроллерах

### 11. Глобальная обработка ошибок
- **401** — не авторизован (AuthenticationException)
- **403** — недостаточно прав (AccessDeniedHttpException / AuthorizationException)
- **404** — модель не найдена или путь не найден
- **409** — бронь уже отменена (BookingAlreadyCancelledException)
- **422** — ошибки валидации (ValidationException)
- Единый формат ответа: `{ success, message, errors (При 422) }`

### 12. Часовые пояса
- База данных хранит все даты в `UTC`
- Клиент передаёт свой часовой пояс в заголовке `X-Timezone`
- При сохранении — конвертация в `UTC`
- При выводе — конвертация обратно в локальное время клиента

### 13. Документация API (Swagger / OpenAPI 3.0)
- Интерактивная документация через Swagger UI
- Описание всех эндпоинтов, параметров, схем ответов
- SecurityScheme для Bearer-токена (можно тестировать прямо из UI)
- Группировка по тегам: `Auth`, `Room`, `Booking`

### 14. Пагинация
- Список комнат (`GET /rooms`) выводится по 15 записей на страницу
- Параметр `page` для переключения страниц

### 15. Production готовность
- Отдельный `php.prod.Dockerfile` для продакшен окружения

## 📋 Требования

- Docker & Docker Compose
- Make (опционально, для удобства)

## 🚀 Быстрый старт

### Клонировать репозиторий
git clone https://github.com/samuraj198/meeting-room-api.git <br>
cd meeting-room-api

### Скопировать .env
cp .env.example .env

### Запустить контейнеры
docker-compose up -d <b>или</b> make up

### Установить зависимости
docker-compose exec app composer install

### Выполнить миграции и сиды
docker-compose exec app php artisan migrate --seed <b>или</b> make artisan -- migrate --seed

### Сгенерировать ключ приложения
docker-compose exec app php artisan key:generate <b>или</b> make artisan key:generate

## 🧪 Тестирование
make test -> запускает все тесты (Feature) <br>
make test-rooms -> запускает тесты для модели Room <br>
make test-bookings -> запускает тесты для модели Booking
